## Context

E8 (Navigate menu parity, PR #99) implemented Go to Declaration, Go to Super Implementation, Go to
Implementation, Go to Test, and Inspect Members. "Inspect Hierarchy" (Alt+Shift+F12) was explicitly
deferred to E8.5 because it needs a custom implementation.

**NetBeans has no `TypeHierarchyQuery` SPI** — confirmed by exhaustive search. The platform exposes
no hierarchy API comparable to IntelliJ's `HierarchyProvider`. IntelliJ sources in
`submodules/IntellijCommunity/…/hierarchy/types/` use `com.intellij.ide.hierarchy.*` APIs that are
not available in NetBeans.

Goal: open a dockable "Type Hierarchy" window (`TopComponent`, `PERSISTENCE_NEVER`) for the class
or interface at the caret. The window shows a `JTree` with two switchable views — supertypes
(upward) and subtypes (downward). Double-clicking a node navigates to that class.

## Implementation details

### 1. `KotlinTypeHierarchyNode.kt` — Model/data

```kotlin
data class KotlinTypeHierarchyNode(
    val name: String,
    val fqName: String?,
    val kind: HierarchyKind,      // CLASS / INTERFACE / OBJECT / ENUM / ANNOTATION
    val psi: KtClassOrObject?,
    val fileObject: FileObject?,
    val children: MutableList<KotlinTypeHierarchyNode> = mutableListOf()
)

enum class HierarchyKind { CLASS, INTERFACE, OBJECT, ENUM, ANNOTATION }
```

`fromPsi(psi, fo)` companion factory fills name/fqName/kind from PSI without `analyze {}`.
Kind is determined by `psi is KtClass && psi.isAnnotation()/isEnum()/isInterface()`, and
`psi is KtObjectDeclaration`.

### 2. `KotlinTypeHierarchyComputer.kt` — Model/service

**`computeSupertypes(decl, session)`** — returns direct Kotlin-source supertypes of `decl`:

```kotlin
analyze(kaKtFile) {
    val symbol = decl.symbol as? KaClassSymbol ?: return emptyList()
    symbol.superTypes                           // sequence of KaType
        .mapNotNull { it.symbol?.psi as? KtClassOrObject }   // import: analysis.api.types.symbol
        .map { KotlinTypeHierarchyNode.fromPsi(it, superFo) }
}
```

Requires import `org.jetbrains.kotlin.analysis.api.types.symbol` for the `KaType.symbol`
extension (not imported by default — causes "Unresolved reference 'psi'" at compile time if
omitted).

**`computeSubtypes(decl, project, session)`** — scans all project `.kt` files; mirrors
`KotlinGoToImplementationsAction`:

```kotlin
for (fo in KotlinPsiManager.getFilesByProject(project)) {
    val searchFile = session.getKtFileForPath(fo.path) ?: continue
    runCatching {
        analyze(searchFile) {
            searchFile.accept(object : KtTreeVisitorVoid() {
                override fun visitClassOrObject(classOrObject: KtClassOrObject) {
                    super.visitClassOrObject(classOrObject)
                    if (classOrObject == decl) return
                    val symbol = runCatching { classOrObject.symbol as? KaClassSymbol }.getOrNull() ?: return
                    val extendsTarget = runCatching {
                        symbol.superTypes.any { it.symbol?.psi == decl }
                    }.getOrNull() ?: return
                    if (extendsTarget) subtypes += KotlinTypeHierarchyNode.fromPsi(classOrObject, fo)
                }
            })
        }
    }
}
```

Each file is wrapped in its own `runCatching` so a single broken file does not abort the scan.

### 3. `KotlinTypeHierarchyPanel.kt` — View (JPanel)

- `JToolBar` with `JToggleButton` pair **Subtypes** (default) / **Supertypes** in a `ButtonGroup`.
- `JTree` with `DefaultTreeModel`; root is the focal class, children are the computed relatives.
- `HierarchyTreeCellRenderer extends DefaultTreeCellRenderer` — shows `name  (pkg)` label,
  greys out nodes whose `fileObject` is null (non-navigable library types).
- Double-click on a node: calls `openFileAtOffset(doc, offset)` from `openDeclaration.kt`.
- `setRoot(rootNode, project, mode)` triggers background recomputation via
  `RequestProcessor.getDefault().post { }` — EDT is never blocked during the project scan.
- Status label at the bottom shows `"N subtype(s)"` / `"N supertype(s)"` / `"Computing…"`.

### 4. `KotlinTypeHierarchyTopComponent.kt` — View (dockable window)

```kotlin
class KotlinTypeHierarchyTopComponent private constructor() : TopComponent() {
    override fun preferredID() = PREFERRED_ID
    override fun getPersistenceType() = PERSISTENCE_NEVER   // not restored at IDE startup

    companion object {
        const val PREFERRED_ID = "KotlinTypeHierarchyTopComponent"

        fun openFor(rootNode: KotlinTypeHierarchyNode, project: Project) {
            val tc = WindowManager.getDefault().findTopComponent(PREFERRED_ID)
                         as? KotlinTypeHierarchyTopComponent
                     ?: KotlinTypeHierarchyTopComponent()
            tc.panel.setRoot(rootNode, project)
            if (!tc.isOpened) tc.open()
            tc.requestActive()
        }
    }
}
```

No `layer.xml` registration needed — window is opened only by the action, never at startup.
`PERSISTENCE_NEVER` means no serialization between IDE sessions.

### 5. `KotlinInspectHierarchyAction.kt` — Controller (BaseAction)

Action name: `"kotlin-inspect-hierarchy"`.

```
1. Get fo, project, KotlinAnalysisAPISession from caret context.
2. findElementAt(caretOffset) → getNonStrictParentOfType(KtClassOrObject) [direct class decl]
   OR getNonStrictParentOfType(KtNamedDeclaration) → its enclosing KtClassOrObject [member at caret]
3. KotlinTypeHierarchyNode.fromPsi(classDecl, classFo) → rootNode
4. SwingUtilities.invokeLater { KotlinTypeHierarchyTopComponent.openFor(rootNode, project) }
```

If neither a class nor a member-inside-class is found at the caret, shows
`"Place caret on a class or interface"` in the status bar.
